# M2-D 合成档案升级与回退演练

本计划适用于方案 A 的目标 Windows x64 本机。候选验证使用独立合成 Profile，正式 Profile 保持封存。发布日期与升级授权另行确认。正式原位恢复保持 HOLD。

## 固定输入与验收基线

- 保留 PR #6 已验收 Head `7c935055926a263b853bdd82adfe57cbae22fc8a` 的便携包，以及 M2-D 候选的同 SHA CI 便携包。分别核对 `build-info.json`、`SHA256SUMS.txt` 和实际 EXE。使用分开的程序目录，避免升级程序覆盖可回退的旧程序。
- 在旧 EXE 的独立合成 Profile 准备至少两名虚构学生、学习记录、已完成和未完成工作事项、含修改历史的成长档案、已完成导入及一笔可安全重试的未完成导入。记录学生 UUID、历史顺序、导入代号和请求 ID、四库身份与 Schema。用结构化比对记录四库业务表，包含初始化标记内容和侧车状态。
- 旧版没有 M2-D 导出入口。正常退出旧版，确认应用进程关闭，在合成数据上单独核对四库的 SQLite checkpoint 与完整性。只有确认无待合并 WAL、目录及文件普通且四份初始化标记齐全后，才可以将这组静止的合成资料复制到一次性导出 Profile。遇到条件不符时停止，保留源文件及侧车。
- 在导出 Profile 用 M2-D 运行完整四库导出。独立校验备份并生成恢复副本，核对四库身份、Schema、摘要、业务关联与旧版基线完全一致。将备份和验证记录存放在应用目录之外。实际升级演练须以这份已验证备份为前置条件。

## 升级与故障注入

1. 关闭旧 EXE，在该轮的合成 Profile 启动 M2-D 候选。确认当前目录为预期原始档案，之前记录的应用身份、Schema、Student UUID、工作和成长历史及 JSON 导入绑定均保持。以相同 JSON 验证识别重复，以原请求编号验证待确认导入可安全重试。正常重开再读记录，另存升级后备份。
2. 为每个故障点从相同的合成基线准备新 Profile。用受控测试进程退出模拟升级在首次打开前、已登记激活但尚未完成、已验证四库但活动选择尚未发布时中断。将原档案、备份和副本的路径、状态与业务基线对照记录。使用测试进程或测试屏障，不做真实断电。
3. 在演练 Profile 启动候选，错误应能明确识别，原档案和备份可读，已中断的激活不会被误判成完整成功。用升级前包生成独立副本，在候选中显式激活，核对四库，在恢复档案写入合成记录并重开。再切回原始档案，确认两份资料各自保留，重新选择已激活档案确认新记录仍在。
4. 旧版兼容性单独演练。查阅两版 Schema 和初始化规则，把已正常退出且通过完整性验证的候选档案制成独立的合成兼容性副本。旧 EXE 仅打开该副本，检查身份、Schema、合法 WAL、四库查询、同一 JSON 防重及写入后重开的行为。旧版启动是否尊重 M2-D 活动选择需单独记录。任何未验证的库、侧车状态或记录差异都阻止旧版直接接管。允许的回退路线优先用升级前验证过的独立恢复副本；两版程序和数据始终可区分。

## 放行证据

每个演练保留旧版与候选 SHA、可验证包、故障阶段、可复现触发步骤、原始与恢复档案的四库核对结果、实际活动目录，以及失败或回退提示。发布前使用整合后的 Windows 产物在目标电脑重跑这套合成演练，核对断网冷启动和中文 Windows 账户。任何版本不兼容、初始化标记不符、数据差异、备份无法验证或无法安全回切均阻止正式发布。启用正式档案与原位恢复分别等待明确批准。
