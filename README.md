# 督学工作台 · Windows 桌面验证

这个 Windows x64 工程用于验证独立安装和 SQLite 持久化。窗口只有一条可新增和修改的虚构记录。

## 构建与验证

开发需 Node 24 与 npm。运行 `npm ci`、`npm run typecheck`、`npm test`、`npm run dist:win`。安装器和解包目录在 `release/`。构建需要获取锁定依赖和打包工具。打包后从 Windows 资源管理器启动应用。无须运行开发服务器。

安装时选择当前用户，并可指定中文或包含空格的安装路径。测试时记录一句虚构内容，保存后关闭重开，核对正文，再修改并确认版本增量。验证包未签名，仅供审阅。

## 数据目录与故障处理

数据默认在 `%LOCALAPPDATA%\SupervisorWorkspace\PR1A\桌面验证\data\workspace.sqlite3`。同级 PR1A profile 独立保存 Chromium 会话和初始化标记，不与其他项目共用。SQLite 由 Electron 内置 Node 驱动。首个事务写入应用标识、结构及 `user_version=1`，以后迁移按顺序在事务中执行。SQLite 使用 WAL 和 FULL 同步模式。提交成功后才显示保存成功。

首次启动需要独立数据目录。初始化标记存在而数据库缺失、数据库为空、损坏、归属错误或版本过高时，窗口显示错误并保留原始数据。如果目录权限有误，先退出应用并保留数据库和对应的 WAL/SHM 文件供检查。当前版本的测试库是明文，限虚构记录。

如果首次初始化中断且窗口提示数据库初始化失败，先完全退出应用。确认这个 `PR1A` 测试目录里只有虚构数据，且没有需要继续使用的旧记录，再把整个 `%LOCALAPPDATA%\SupervisorWorkspace\PR1A\` 目录改名为同级的保留副本。主库、可能存在的 WAL/SHM 及初始化标记应随目录一同保留。重启应用会在原路径初始化一个空的测试库。若需恢复旧记录，先保全原目录并在副本上检查，避免单独搬移 SQLite 附属文件。

窗口加载包内资源，使用 Chromium 离线会话和受限 IPC。界面只可请求读取和保存单条记录。主进程验证调用来源、输入和记录版本。

## 回滚

关闭窗口并在 Windows 的已安装应用列表卸载 Supervisor Workspace PR1A。卸载保留测试数据库。需要检查或备份时，先完全关闭这个应用，再保留完整的 PR1A 数据目录。旧代码若不支持新库结构，在副本上用旧版本验证，保留原库以供恢复。
