# v0.2.1 联合候选正式升级准备方案

当前结论：正式升级 HOLD。本文只制定顺序，不执行正式数据备份、恢复、安装、快捷方式更新或应用退出。实际候选 HEAD、ZIP 与 SHA-256 见交付清单；必须以最终审核的固定身份为准。

## 身份与升级前提

当前正式程序为 `D:\SupervisorWorkspace\App\Versions\a1e5a3b49fe50a8a7db75d219d351e82f9680911\SupervisorWorkspace-MVP.exe`，内置 0.2.0，构建来源 CI 45400265657。正式数据根通过正在运行的进程 userData 线索为 `D:\SupervisorWorkspace\Profiles\Primary\profile`；升级执行当天必须再次核实活动档案，不能假定没有切到恢复副本。

候选版本为 0.2.1，包含 PR 15/16/17 和两个状态往返修复。只有用户批准候选、身份核实、可恢复正式备份、关键回归完成且无安全阻断时才可进入执行。CI 上传失败必须保持可见；如审查要求 CI 可下载产物，需配额恢复后成功上传，不能拿本地产物冒充 CI 产物。

## 计划执行顺序

1. 用户核对并批准最终 HEAD、版本、ZIP 外部 SHA-256、内部 build-info 和逐文件 SHA256SUMS。检查 Windows 信任提示的处理方式；不通过关闭系统安全功能完成安装。
2. 在正式旧程序中保存或明确处理草稿、学习块、待核对请求及未完成导入，停止业务写入。通过完整备份功能导出活动五库 SWBACK2 到批准目录。校验文件摘要，并在获准的独立数据根恢复核对；真实记录只留本机，证据仅记摘要、数量和结果，不上传学生内容。
3. 将已校验备份复制到用户指定独立介质，再次比较 SHA-256。保留当前 EXE、app.asar、安装清单、原快捷方式身份及原数据根。此时才具备可恢复备份条件；本轮合成验证不能替代它。
4. 正常退出正式旧程序，确认相关主/子进程退出、无写入进行。发现异常退出、待核对状态或不明 WAL/SHM/journal 时保留文件与现场，停止升级，不删除侧车强行继续。
5. 将验证后的候选程序安装到新的 `App\Versions\<候选SHA>` 目录，不覆盖旧目录。可沿用包内 Production-Admission.ps1 的 Install 操作校验程序文件；已有 Primary 不运行 PrepareLegacy 或 ActivatePrimary，不做重复首次激活或原位恢复。
6. 在授权下创建或调整指向新 SHA 的启动入口，记录原入口以便回退。现有脚本的 CreateShortcut 对同名入口会拒绝，不能直接用它覆盖旧入口；具体入口操作须在执行方案中明确。不同时运行两个程序访问同一活动档案。
7. 启动候选，核对模式为正式、本机数据位置、学生数量和身份对应、既有家长诉求、成长资料、学习历史、成绩原值与趋势、导入来源、排课/到课/任务、备份状态。真实内容由用户本机核对，不上传截图或日志中的学生信息。
8. 正常退出并重开，确认状态与记录一致，按批准的最小业务流程完成实际使用验收；再导出并验证升级后备份。用户验收完成前保留旧程序及全部已校验备份，不清理历史版本。

本批 schema 仍为 M1 v6、其余四库 v1，SWBACK2 不变。无数据迁移不等于不需要备份或正式使用验收。

## 失败与回退

- 未启动候选或尚无正式业务写入：停止新程序，保留失败现场，在核对活动档案未改变后，经授权恢复原启动入口和保留的 0.2.0 程序，不把旧备份覆盖当前数据。
- 候选已有正式写入：先停止业务，导出并验证当前活动档案，保全新增写入、当前五库、选择记录及原备份。尽管 schema 相同，也不得直接把旧备份或旧 Primary 重新设为工作档案而丢弃新记录。先在独立副本核对旧程序读兼容性及差异，再审批保留新增记录的回退路径。
- 数据损坏或打开失败：保留原目录及侧车，在独立根恢复已校验备份，核对差异与未备份新增记录；得到恢复授权后再决定激活目标。不能通过删除数据库或标记自动修复。
- 档案已切到恢复副本：回切会改变可见数据，两份档案的后续写入不自动合并。先导出两边资料、核对差异，明确目标和授权后操作。
- 旧 0.2.0 缺少本批维护保护，回退后相关风险重新存在，必要时仅保持停工/只读核对；不能因为程序可启动就恢复正常业务写入。
