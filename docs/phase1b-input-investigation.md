# Phase 1B 满分数值变化调查

状态：**保存或切换后数值变化尚未复现，根因未确认，未实施产品修复，无 Phase 1B 修复 PR。** 不阻塞独立审查 Phase 1A。成绩输入、保存和恢复代码相对 main 未改变。

## 四层数值核对

在新建 Windows 合成档案中输入得分 90.25、满分 150.50，真实应用记录如下：

| 层级 | 观察 |
| --- | --- |
| 保存前输入框显示 | `150.50` |
| IPC 提交请求 fields.maximum | `150.50` |
| 正常退出后只读 SQLite payload.maximum | `150.50` |
| 重新启动、进入历史编辑后的输入框 | `150.50` |

提交请求通过仅在测试进程中包裹 IPC handler 采集。SQLite 只读检查仅访问该合成档案；测试没有更改正式进程或正式数据。

## 已排查范围

| 操作 | 结果 |
| --- | --- |
| 逐字键入、清空、替换、真实剪贴板粘贴 | 完整小数输入成功，清空不填零，粘贴值一致 |
| 输入框聚焦及失焦 | `150.50` 保留 |
| 切换学科、类别和详情页签 | 本轮样本未改满分；Phase 0 另有直接修改学科验证 |
| 连续新增 | 第二条满分初始为空，保存为 50，第一条仍为 150.50 |
| 编辑历史得分 | 旧考试 60 改为 88.25 后立即刷新，未改其他记录满分 |
| 关闭重开、切换学生 | 数值保持、成绩按学生隔离 |
| 保存回执延迟、快速重复提交 | 草稿保持 150.50，只发出一次请求；忙碌期间学生切换被阻止 |
| 旧学生查询延迟，切换另一学生后再释放 | 另一学生保持自己的唯一成绩，没有采用旧响应 |
| 原生上方向键 | 100 → 101，确认数字输入框原生步进 |
| 聚焦后正反滚轮 | 本轮两次仍为 150.50，未复现滚轮改值 |

上方向键步进不等于用户反馈的保存/切换异常。不能把它宣称为已确认根因。数字框小数中间态受浏览器原生行为影响：输入 `150.` 时 DOM value 暂为 `150`，继续输入后可形成 `150.50`，未观察到持久化为另一数值。图表数字格式可能去掉尾零，但原始记录保持字符串；Phase 1A 默认得分率展示也不会回写满分。

异步实验覆盖两个明确屏障及快速重复提交，不能证明全部调度时序、鼠标/触控板组合或用户未知操作都没有问题。尚未取得用户实际变化前后数值和最小操作序列，因此保留“尚未复现”。

## 下次发生时的简单取证

1. 先不要反复覆盖保存。记下“输入时、保存后、切换后”各自的满分，例如 `150 → 100`。
2. 记下切换对象：学科、考试类别、图表筛选、详情页签还是学生；是否使用滚轮、上下方向键、粘贴。
3. 若方便，用虚构学生按相同步骤试一次。只提供虚构记录的操作描述或脱敏截图，不发送真实学生数据库。
4. 如仅为 `150.50 → 150.5`，说明发生位置是输入框、历史列表还是图表标签，以区分格式变化和实际数值变化。

## 测试工具边界

一次原生粘贴实验的测试脚本在恢复剪贴板时遇到 Electron 45 API 差异，剪贴板可能曾被留为测试值 `150.50`。脚本已改为先完整读取各类型内容、构造可写 ClipboardItem 并预验证，再在 finally 恢复。原内容未上传或写入证据，但失败前的旧剪贴板内容无法由后续测试恢复；需要时应从原处重新复制。此问题发生于测试工具，不是成绩输入异常的根因。

没有针对推测原因重构输入器，也没有新增正式诊断日志。后续如取得最小反例，应从 main 重新核实并建立独立 Phase 1B 修复分支、回归和 Draft PR。
