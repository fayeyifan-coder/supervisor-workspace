# R3-B② 家长诉求与跟进

在 M1 v3 独立合成五库 Profile 的学生详情中登记家长诉求。原始条目包括日期、来源角色、类别、原文和可选下次跟进日期。跟进以追加记录保存日期、进展说明、状态和可选下次跟进日期。状态可设为待跟进、跟进中、已结案；显式追加待跟进或跟进中记录可以重启已结案事项。原文与既有跟进作为历史保留。当前状态和下次日期取自最近的已保存跟进。

诉求与成长评价、学习事实分别展示。身份关联使用既有 M1 学生 UUID。日期采用 Asia/Shanghai，跟进日期不早于上一条记录。用户在本机手工填写；本阶段用虚构学生、角色及内容验证。

## 存储和恢复

- M1 保留原应用身份，`user_version=3` 对应 `mvp-v3`。新增 `parent_concerns` 和 `parent_followups`，以外键分别关联学生及原诉求。跟进修订从 1 开始。写入在原 M1 事务保护下执行，使用预期修订和请求 UUID，拒绝过期修订、跨学生关联与异载荷重放。落库的记录就是回执。
- 五库格式仍为 SWBACK2。M1 v3 清单包含新版 Schema、初始化标记与镜像摘要。备份和恢复校验包含诉求归属、日期、请求唯一性及跟进修订连续性。
- M1 v1 四库或五库备份可升级为新隔离五库 v3。四库来源另建空教务库。M1 v2 的 SWBACK2 升级保留已有基础资料、编辑历史、待核对编辑、其他四库镜像，新增两张家长记录表为空。转换只发生在已验证备份的内存副本，带来源版本与摘要。展示恢复确认后排他新建，原包和原 Profile 均保留。
- v3 使用单独合成目录，启动时拒绝其他版本及不符标记。v1／v2 开启入口拒绝降级读取 v3。SWBACK2 v3 恢复仍须显式激活，保留原 Profile 和回切路径。

## 本阶段验证范围

验证类型检查、数据库、旧版本与新版本备份、未 checkpoint 的 WAL、损坏历史拒绝、重开、版本冲突、幂等及跨学生隔离。回执不明时当前会话保留原请求编号，可重新读取或原样重试。重启后可核对已落库的历史与请求编号，尚未持久化的草稿不跨进程恢复。该限制和完整人工、便携包实机验收留待集中复核。

报名与到期提醒、成绩及提分方案、总课表、到校看板分别在后续独立提交进行。正式整合、D 盘正式部署和真实学生使用保持 HOLD。
