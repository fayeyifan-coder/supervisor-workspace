# R3-B 基础档案安全编辑

候选仅在 Windows 上以既有合成启动开关和 `sw-r3b-…` 档案名启用。新版根为 `sw-r3b-profiles`，既有四库、五库 v1、正式 Profile、原位恢复均沿用各自准入条件。会话保留 M1 的学生 UUID 和创建时间，编辑只更新代号、年级、学科、基础目标和备注。

## 数据与恢复

- M1 保留 `application_id=0x53574d31`。`user_version=2` 配套 `mvp-v2` 初始化标记。原有学生表与学习记录表结构保留。
- `student_edits` 按学生记录从 1 开始的连续修订。请求 UUID 是主键，另有学生 UUID 和修订号的唯一约束。保存修改前后字段、修改时间和版本。当前学生字段必须和最后一版吻合，第一版的修改前字段保留原创建回执的比较依据。
- `student_edit_pending` 按学生保存待确认的规范请求。先独立提交这一行，再在同一事务更新 M1 学生和新增历史回执。回执可用后结束待确认请求。应用重开可从待确认表读取原请求，从历史核对是否成功。已提交请求不能被误报为放弃。同请求同内容回放原回执，异载荷或过期版本提示核对。回滚失效后关闭读写与备份入口，须重开核对。
- 两张表均在现有 M1 库中。SWBACK2 固定锁下读取已提交 WAL，连同其他四库快照保存历史与待核对请求。逐库验证应用身份、Schema、初始化标记、摘要及完整性；M1 v2 额外验证历史连续性、各版本字段、学生现值和请求关系。M1 仍作为跨库学生 UUID 唯一来源。

## 兼容矩阵

| 输入 | 原 v1 工作台或新四库／五库 v1 模式 | R3-B 五库 v2 模式 |
| --- | --- | --- |
| 现有 M1 v1 数据目录 | 沿用原入口 | v2 启动拒绝，先从源版导出受支持的备份 |
| SWBACK1，M1 v1 | 四库恢复或既有独立四转五 | 校验旧包，在新副本保持四库业务数据，生成空教务库，并升级 M1 |
| SWBACK2，M1 v1 | 正常五库恢复 | 校验后在新副本升级 M1，其他四库镜像保持逐字节一致 |
| SWBACK2，M1 v2 | 拒绝，禁止降级或裁掉历史 | 校验后独立恢复，保留历史和请求 |
| 损坏、不合法 Schema／初始化标记、未验证侧车 | 阻断用库 | 阻断用库并保留现场 |

升级仅处理原生受控读取并已校验的包内容。M1 v1 的普通 SQLite 镜像在内存副本加空的编辑表与版本标记，再重建、验证并生成新包；无需以可写方式打开 v1 源数据库。清单分别记录四转五及 M1 升级来源摘要。原包和原档案完整保留。没有历史编辑记录的旧学生从修订 0 开始。

恢复写入新的隔离路径。普通启动仍拦截恢复目录。用户单独确认激活，关闭应用并确认数据库关闭后安排切换。重开复核清单和初始化状态，再打开受控生成的活动副本。回退使用「返回原始档案」或已激活过的副本；旧程序只使用其独立旧档案目录，且旧版 M1 读写入口拒绝 v2 文件。

本阶段仍按可信单 Windows 用户验收。Windows 进程异常退出用可重复的提交屏障验证，整机断电未纳入。本功能在正式 D 盘环境的迁移和放行另行审查。
