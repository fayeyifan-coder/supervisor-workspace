## 业务问题与修复

| 严重程度 | 风险与反例 | 处理 |
| --- | --- | --- |
| P1 | 活动学习块未结束时签退成功，导致出勤与学习事实不一致。旧入口还允许在签退后开始关联学习块。 | `1f5502f` 存储拒绝两种操作，界面禁用并说明。新增反例先在基线验证失败，再在修复后通过。 |
| P1 | 任务仍在进行时结束学习块成功，任务不能在已结束块中补写结果。 | `1f5502f` 结束前先完成或跳过进行中的任务。已有尚未开始的项目保留原状态。 |
| P2 | 签退后课表仍使用出勤枚举显示已到校，而看板显示已签退。看板原应到值只有按安排计数，同人多期容易被当成人数。 | `64ec132` 同步签退展示，独立列出人数和人次，标明取消是否纳入。迟到按上海分钟比较。 |
| P2 | 同学科、同类别的不同满分考试曾自动连成一条趋势，缺少难度说明。 | `6c2e520` 按学科、考试类别、满分分别绘图，提醒同组仍可能不同难度。 |
| P3 | 续费后旧期与新期同时存在，旧期显示已到期容易被误读成新期失效。 | `64ec132` 界面明确按期计算，原期历史保留。 |

### 留给整体界面验收

- 旧合成档案如果已有签退和活动学习块并存的历史，修复不会重写这些记录。需由验收人员核对旧数据表现。未签到仍可按原规则登记学习事实，出勤汇总保持待到校或未签到；在人工环节确认这一口径是否需要更醒目的提示。
- 多期报名分别保留有效期，未引入按课程自动合并和续费推断。同满分趋势有难度提示，未建立试卷难度或等值评分模型。
- 高密度卡片操作、键盘顺序、长文字截取和跨小窗口的阅读效率留待人工体验。整体界面人工验收可开始。
- 正式发布和整合仍 HOLD。PR #1 两项真实环境补验、最终便携包及正式 D 盘部署仍按先前准入处理。

证据存放于本次独立实验目录。脚本与结果为 `business-electron.cjs`、`business-electron.txt`、`operation-history.txt`、`baseline-business-repro.txt`、`learning-regression.txt`、`final-tests.txt`。
