# v0.2 正式使用准入

本阶段使用合成档案验证。正式开通须单独授权。安全边界沿用可信单用户 Windows。使用固定 NTFS 本地卷，具有同一账户写权限的恶意进程主动修改本机文件仍超出保护范围。

## 安装与首次激活

| 目录 | 用途 |
| --- | --- |
| D:\SupervisorWorkspace\App\Versions\<提交 SHA> | 校验后发布的独立版本。保留先前程序。 |
| D:\SupervisorWorkspace\Profiles\Primary | 正式五库和受控激活记录。原始数据库在 profile\data，恢复副本属于同一档案根。 |
| D:\SupervisorWorkspace\Profiles\Synthetic | 与正式档案分离的合成资料区域。部署演练使用下文独立根。 |
| D:\SupervisorWorkspace\Profiles\Staging | 独立迁移资料和失败现场。 |
| D:\SupervisorWorkspace\Exports | 默认导出目录。另留一份已校验的独立介质副本。 |
| D:\SupervisorWorkspace\Logs | 程序和崩溃日志。 |

Windows CI 提供可校验的解包目录、部署脚本和逐文件 SHA-256 清单。先验证可信归档的外部 SHA-256。使用 Windows PowerShell 5.1 或更新版本运行包内的 deploy/Production-Admission.ps1。所有验收命令都带上同一个独立目录，例如 D:\Codex-Development\Builds\sw-production-admission- 后接 32 位小写十六进制。此目录以 -AcceptanceRoot 指定。正式部署才省略它。

1. **安装版本** — -Operation Install -Commit <SHA> -PackageRoot <解包目录>。暂存复制、逐文件校验后发布新版本。保留现有目录。当前候选未签名，正式分发须确认 Windows 信任处理方式。
2. **保全旧版** — 保存旧 EXE、原档案、原快捷方式身份及摘要，另外保管独立副本。正常退出旧程序。存在 WAL、SHM 或 journal 时停止，由获准维护人员先在隔离副本核对。保留原主库和侧车。
3. **迁移准备** — -Operation PrepareLegacy -Commit <SHA> -InputPath <旧 M1 v1 数据库所在目录>。原生组件只读打开静止源文件，拒绝可写占用、异常链接、未知文件和不匹配标记。验证隔离副本，保存 SWBACK1，升级并发布 M1 v6 的 SWBACK2。新增教务、工作、成长及导入库均为空。核对原摘要、学生 UUID 和学习历史。
4. **确认激活** — -Operation ActivatePrimary -Commit <SHA> -InputPath <SWBACK2> -ExpectedSha256 <已核对摘要>。再次验证备份，另存独立副本，完成五库及初始化记录后才发布新 Primary。已有 Primary 一律拒绝覆盖。
5. **创建入口** — -Operation CreateShortcut -Commit <SHA>。验收入口写在隔离根的 Shortcuts。正式模式经授权后在桌面创建新入口。发现同名入口会中止。双击直接进入上海当天全局总课表，无需 PowerShell、npm 或合成变量。
6. **上线核验** — 核对默认档案、版本及业务记录。保存、正常退出、重开、导出 SWBACK2，并在独立档案验证恢复、激活和回切。档案目录、版本、标记或活动选择记录异常时停止启动，保留现场。合法 SQLite 运行侧车仍受支持。

## 失败及回切

- 迁移失败时保留源、备份、日志和暂存现场。核对后用新的暂存位置重试。
- 旧版 M1 拒绝 v6 库。旧版与新版档案使用不同位置。新版本尚无正式写入时，经批准可返回原程序和原 v1 档案。
- 新版本已有正式写入时，暂停业务并导出、验证当前活动档案的 SWBACK2。保留新增记录，完成数据差异核对和回退授权前禁止把旧档案重新作为活动工作档案。
- v0.2 的双向 Profile 回切保留原档案和活动恢复副本各自的写入。切换会改变当前可见档案。由操作者核对，程序不会合并两份写入。

## 教务待核对描述符完全丢失

1. 看到异常后停止重试。保留现场和独立旧备份。独立 guard 在原描述符及载荷同时丢失时仍阻止写入。
2. 暂停业务写入，从当前档案导出 SWBACK2。用 -Operation ReviewOperations -Commit <SHA> -InputPath <备份> 核对已提交回执。结合排课、学习记录、学生 UUID 和修订号确认事实。结果最多列 500 条，若截断或结果不明确，须继续核对历史。
3. v0.2.1 会拒绝从仍有待确认教务请求的活动档案切换。先通过现有核对入口结束能确认的请求。原描述符已经彻底损坏时，保留原档案、异常证据与已校验备份，暂停操作并安排受控恢复。可以先在隔离环境核对恢复副本，正式激活须另行确认。请保留现有请求标记。
4. 三份证据均被外部删除时无法判断是否曾有待核对请求。新增 guard 之前的记录同样保留这个边界。

## 遗留发布准入

- 单库 32 MiB、备份包 161 MiB 上限。程序根据系统可用内存保守预判。Windows Job 私有配额及突发内存耗尽可能造成进程级中断，仍由备份完整性标记和原档案保护机制阻止误认成功。
- 锁定依赖审计为 6 项中危，完整生产依赖审计为 0。中危来自 electron-builder 打包工具链，根告警是 minimatch 的特定 glob 可造成拒绝服务。建议维持可信构建输入和固定依赖，在下一次工具链常规升级时重新核验。
- 整机断电及存储控制器行为保持未验证。进程级失败和不完整备份拒绝已有独立证据。
- PR #1 的真实中文 Windows 账户和完全断网冷启动保持 HOLD。用获准的备用 Windows 电脑或隔离 VM，事先保存固定 PR #1 产物及哈希。创建并登录真实中文名称测试账户，记录脱敏的账户名、Windows Profile 路径和程序数据目录。关机前断开全部虚拟或物理网络，冷启动后记录网络状态。双击应用、建立虚构记录、正常退出、重开两次。记录 Windows 版本、产物哈希、退出结果、SQLite 完整性和错误日志。
